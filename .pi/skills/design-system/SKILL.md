# Design System Grounding

Before proposing or critiquing UI, locate the nearest target-project `DESIGN.md` and treat its decisions as constraints. If it is missing or a section is unfilled, state the gap and request direction; do not invent house tokens or claim an ungrounded choice is established.

Use this portable Stitch schema when creating or completing a design-system document. Keep values concrete (tokens, examples, and constraints), rather than aesthetic adjectives alone.

## Color

Document named color tokens, semantic roles, contrast constraints, and dark-mode behavior.

## Typography

Document display, body, and utility faces; the type scale; weights; line heights; and fallback rules.

## Spacing

Document the spacing scale, density rules, and responsive adjustments.

## Layout

Document grids, breakpoints, page regions, content widths, and responsive behavior.

## Components

Document component variants, states, interaction affordances, and accessibility constraints.

## Motion

Document timing, easing, meaningful transitions, and reduced-motion behavior.

## Voice

Document interface-writing tone, vocabulary, capitalization, and error/empty-state guidance.

## Brand

Document visual direction, signature elements, imagery, references, and approved examples.

## Anti-patterns

Document prohibited defaults, visual clichés, inaccessible patterns, and known inconsistencies to avoid.
